Без понимания криптограции, а именно криптографических ключей, невозможно понять, как вообще Bitcoin доказывает, что деньги принадлежат Вам.

#### Приватный ключ (private key)

Что это: обычное случайное число, но огромное $-$ 256 бит.

```
Пример приватного ключа (в hex):
E9873D79C6D87DC0FB6A5778633389F4453213303DA61F20BD67FC233AA33262
```

Почему это работает:
- диапазон возможных значений настолько огромен, что подобрать чужой приватный ключ перебором физически невозможно;
- приватный ключ $-$ это единственное, что доказывает владение монетами. Кто знает приватный ключ, тот и распоряжается средствами;
- генерируется случайным образом на устройстве пользователя (обычно кошелек сам генерирует), никогда не передается по сети.

> [!note] Приватный ключ не хранится в блокчейне
Блокчейн вообще ничего не знает про чей-либо приватный ключ. Он существует только у пользователя (в файле кошелька, на бумаге, в железном кошельке и т.д.)

#### От приватного ключа к публичному: эллиптическая криптография (ECDSA)

Bitcoin использует алгоритм **ECDSA** (Elliptic Curve Digital Signature Algorithm) на конкретной кривой под названием **secp256k1**, при котором:
- функция легко вычисляется в одну сторону (приватный ключ $\Rightarrow$ публичный ключ)
- практически невозможно вычислить в обратную сторону (публичный ключ $\Rightarrow$ приватный ключ).
$-$ это называется **односторонняя функция** (one-way function). 

Математически: 

```
Публичный ключ = Приватный ключ × G
```

где `G` $-$ фиксированная точка на эллиптической кривой, а умножение $-$ это специальная операция умножения точки на кривой, определенная в теории эллиптических кривых.

Зная только публичный ключ, восстановить приватный можно было бы только полным перебором, что заняло бы больше времени, чем существует Вселенная, даже на самых мощных суперкомпьютерах.

```
Приватный ключ (256 бит, секрет)
|
| ECDSA / secp256k1
v
Публичный ключ (можно показывать всем)
```

#### От публичного ключа к Bitcoin-адресу

Публичный ключ $-$ это не секрет, но в качестве адреса его не используют. Вместо этого его сжимают и хешируют, чтобы адрес получился короче и надежнее.

Цепочка преобразований:

```
1. Публичный ключ
|
| SHA-256
v
2. Хеш SHA-256
|
| RIPEMD-160
v
3. Хеш RIPEMD-160 (еще называется Hash160)
|
| добавление версии сети + контрольная сумма (checksum)
| кодирование Base58Check (или Bech32 для новых адресов)
v
4. Bitcoin-адрес
```

#### Зачем нужны два разных хеша (SHA-256, а потом RIPEMD-160), а не один?

Из-за двух хешей конечный адрес получается короче: RIPEMD-160 дает 160 бит вместо 256.

Двойное хеширование разными алгоритмами $-$ дополнительный уровень защиты. Даже если в одном из алгоритмов теоретически найдут уязвимость, второй слой все еще защищает.

Для добавления контрольной суммы (**checksum**), чтобы при опечатках при вводе адреса кошелек сразу видел, что адрес невалиден.

#### Проверка цифровой подписи

При отправке Bitcoin вводится не пароль, а подписывается транзакция **приватным ключом**.

Как это работает:
1. Формируется текст транзакции: кому, сколько, с какого адреса.
2. С помощью приватного ключа и алгоритма ECDSA создается подпись $-$ уникальный набор данных, зависящий и от содержимого транзакции, и от приватного ключа
3. Подпись прикрепляется к транзакции и рассылается по сети.
4. Любой узел сети может проверить подпись, используя только публичный ключ (который тоже прилагается к транзакции) и убедиться, что подпись действительно создана владельцем этого приватного ключа и транзакция не была изменена после подписания.

> [!tip] Проверка подписи не требует знания приватного ключа

```
Подписание:   Приватный ключ + Транзакция           -> Подпись
Проверка:     Публичный ключ + Транзакция + Подпись -> true/false
```

Это решает главную проблему децентрализованных систем: как доказать право собственности без центрального арбитра, который знает всех клиентов.
#### Кошелек (wallet)

> [!warning] Кошелек хранит монеты

Монеты нигде физически не хранятся, они существуют только как записи в блокчейне (точнее, как не израсходованные выходы транзакций, UTXO, но об этом в следующей теме). Кошелек хранит только приватные ключи и производные от них публичные ключи/адреса.

Кошелек $-$ это по сути программа-менеджер ключей + интерфейс для создания и подписания транзакций

#### Виды кошельков

| Тип                                         | Особенность                                                                                                                  |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **Hot wallet**                              | Подключен к интернету (мобильное приложение, биржа). Это удобно, но менее безопасно                                          |
| **Cold wallet**                             | Оффлайн-хранение (железный кошелек, бумажный кошелек). Это безопаснее чем Hot wallet и лучше всего подходит для крупных сумм |
| **HD-кошелек** (Hierarchical Deterministic) | Из одной seed-фразы (12-24 слова) генерируется целое дерево ключей — не нужно хранить каждый ключ отдельно                   |
