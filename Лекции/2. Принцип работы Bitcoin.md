Основа Bitcoin $-$ это защищенная база данных для всех платежей, которую одновременно используют все пользователи. 

Пока запись о платеже не попала в эту базу данных он считается нет подтвержденным.

#### Централизованные системы

В обычной банковской системе есть один центральный узел (банк, платежная система), который хранит единственную корректную версию базы данных со всеми счетами и транзакциями:
- Плюсы: быстро, просто, есть кому разбираться со спорами
- Минусы: нужно доверять этому центру; он может заблокировать счет, изменить данные, стать целью атаки, обанкротиться, ввести цензуру транзакций

#### Децентрализованные системы

Идея Bitcoin $-$ убрать единый центр доверия. Вместо одного сервера $-$ тысячи независимых компьютеров (**nodes**) по всему миру, каждый из которых хранит полную копию базы данных всех транзакций (это и есть **blockchain**).


> [!tip] Bitcoin
> это защищенная база данных для всех платежей, которую одновременно используют все пользователи

Это значит:
- Нет одного главного сервера;
- Каждый узел сети видит одну и ту же историю транзакций;
- Чтобы обмануть систему, нужно взломать/подделать данные сразу у большинства узлов одновременно, что практически невозможно при большой сети.

#### Как транзакция становится подтвержденной?

**Шаг 1. Отправка транзакции**  
Пользователь подписывает транзакцию своим приватным ключом и рассылает ее по сети всем соседним узлам, а те дальше передают ее другим (**broadcast**).

**Шаг 2. Мемпул (mempool)**  
Транзакция попадает в зал ожидания $-$ пул не подтвержденных транзакций, которые видят майнеры/валидаторы, но которые еще не записаны в blockchain. На этом этапе транзакцию теоретически можно отменить или заменить (**двойная трата**).

**Шаг 3. Майнинг / включение в блок**  
Майнеры собирают транзакции из мемпула в блок и решают криптографическую задачу (**Proof-of-Work = PoW**), т.е. перебирают числа (число **nonce** из блока), чтобы хеш блока удовлетворял условию сложности сети.

**Шаг 4. Подтверждение (confirmation)**  
Как только блок найден и добавлен в цепочку $-$ все транзакции внутри него получают **1 подтверждение**. Каждый следующий блок, добавленный поверх, добавляет еще одно подтверждение. Обычно считается, что после **6 подтверждений** транзакцию практически невозможно отменить.

#### Почему это называется цепочка (chain)?

Каждый новый блок содержит хеш предыдущего блока. Получается цепочка блоков:

```
Блок №1 (хеш) -> Блок №2 (хеш блока №1 внутри) -> Блок №3 (хеш блока №2 внутри) -> ...
```

Если кто-то попытается подделать старую транзакцию в блоке №1, изменится хеш этого блока $\Rightarrow$ сломается связь с блоком №2 $\Rightarrow$ все последующие блоки станут невалидными. А поскольку копия цепочки есть у тысяч узлов, сеть просто отвергнет подделанную версию.

#### Как узлы договариваются между собой?

Раз нет центрального арбитра, нужен механизм, по которому все узлы соглашаются, какая версия базы данных верна.

| Механизм                 | Как работает                                                                                   | Где используется                 |
| ------------------------ | ---------------------------------------------------------------------------------------------- | -------------------------------- |
| **Proof-of-Work (PoW)**  | Майнеры тратят вычислительную мощность на решение задачи. Побеждает тот, кто нашел блок первым | Bitcoin                          |
| **Proof-of-Stake (PoS)** | Валидаторы замораживают (стейкают) монеты. Право создать блок выдается пропорционально доле    | Ethereum (с 2022), многие другие |

> [!tip] Правило
> Побеждаем самая длинная цепочка $-$ если два узла нашли блок одновременно, сеть в итоге сходится к той ветке, на которую пришло больше вычислительной работы
